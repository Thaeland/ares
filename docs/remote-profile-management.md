# Remote profiles and agent transfer

Both Classic and NextGen route **More → Profiles** to the same Flutter screen. Choosing a roster row creates a second profile-bound owner; it does not change the saved connection, active chat, sticky CLI profile or Hermes installation. The screen requires matching connection, origin, install ID and canonical profile. Both the originating and selected targets fence requests. An account edit revokes them. The *Applies to* preference belongs to the issuing gateway object; a name is a UI hint, not write authority.

## Contracts for other management lanes

Call `ProfileRoster.read(await pane.bind(owner.route()))`. `roster.names` contains canonical IDs and display labels; `roster.appliesTo` is a previously selected ID only when still present on the same installation. Construct a separate gateway from the originating saved connection with only `gatewayProfile` changed. Bind its own pane, then `roster.settings(scopedTarget, name)` to get `RemoteProfileAdmin`. Close the child pane/client when leaving. Do not persist either target or resolve it through the last-used gateway. Add typed feature operations in their own workspace-library part, not a renderer-supplied URL, shell or RPC string.

The API baseline is Hermes `b7ee21c14e38316273f88d8ed112491ba1c87d15`. Relevant handlers: `tui_gateway/methods_profiles.py`, `hermes_cli/web_routers/{profiles,messaging,ops,uploads,files,status,transfer,actions}.py`, `hermes_cli/{cloud_agents,staged_uploads,backup_keep_host}.py`. Compare `apps/desktop/src/store/profile-share.ts`, `src/app/{profiles,messaging,webhooks}` and `src/lib/agent-transfer.ts` under `apps/desktop`.

| User action | Actual operation and checks |
|---|---|
| Create / clone | `profiles.create` plus a fresh `profiles.list`. No shell alias, channel cloning, credential mirroring or shared auth requested. Cloning the named source may still copy provider credentials from its config. |
| Rename / delete | PATCH/DELETE the selected canonical profile. Default has a display label only; it cannot be deleted. Delete requires typing the exact ID. Verify the machine roster; report unsettled host identity separately. |
| Edit persona | Read `/profiles/{name}/soul`, compare the originally displayed snapshot immediately before PUT, then read it back. The host has no atomic SOUL revision precondition. |
| Channels / DM pairing | Read the selected profile's catalog. Submit only edited env keys, explicit clears and enabled state. Never replay a masked preview. Verify enablement, key presence or removal, and non-secret list values. Use per-request IDs for approval and an exact platform/user for revocation. Older rows lacking a verifiable ID must pair again. A saved setting is not proof a bot connected. |
| Telegram bot creation | The host starts the pairing, retains the poll/bot tokens and returns an expiring `t.me/newbot` QR payload. Draw it locally, check readiness, confirm numeric allowed IDs and the server's restart attempt. Cancellation never applies the bot. No QR image service or auto-launch of a URL. |
| Inbound webhooks | Enable service with restart warning. Create a named, signature-pinned route with event filters, prompt, skills, processing vs direct delivery and optional chat ID. One-time secret reveal, separated from route inventory. Confirm toggle/delete and reload. Upstream POST is an upsert, not an atomic create-only request; the client checks for an existing route and warns of a racing registration. |
| Share a profile | Stock host export/import uses a CLI-compatible `.tar.gz` and new destination ID. For device sharing, review individual plain files and re-encode only those selected. Portable set: persona, config, profile metadata, Markdown skill files, cron jobs and a pre-existing `desktop.json`. No symlinks, arbitrary scripts, databases, `.env` or account stores. Text can still contain private information. Nothing checked by default. 16 MiB compressed / 32 MiB expanded / 4,096 headers / 1 MiB per reviewable text file. |
| Import from device | Upload the reviewed, reconstructed bundle via `/api/chat/file-upload` to the explicitly scoped host (private staging, not a chat message). Match the install ID, exact profile home, unique staged path and byte count before `/profiles/import`. Known host-side archives have a separate trusted-operator flow. No fallback to a broader file root if a managed download is denied. |
| Back up the agent | `/ops/backup` starts a **whole-home** backup on the selected installation. The archive can contain credentials. Check the exact backup PID and exit code before offering a local save. Device save is bounded at 32 MiB; larger archives stay on the gateway. This does not export Ares preferences or saved gateway logins. |
| Transfer to Cloud | Discover orgs/agents via the source profile's `/cloud/agents`. Require a unique separately authenticated saved destination matching the discovered HTTPS Cloud origin, a distinct machine, `default` target and `import_keep_host: 1`. Type the destination agent ID. Recheck owners, copy bounded chunks with exact offsets, stable size and upload ID, then request keep-host restore. Report byte progress, messaging-off and gateway-down results. Cancellation stops before restore; it does not kill an already-started host backup or restore. |
| Undo | Keep the first validated pre-transfer archive reported by the matching import PID, including a partial restore. Persist only a destination-bound fingerprint, not credentials or the archive path. Reopening requires the same authenticated Cloud target, installation, PID and matching server-reported undo path. A stale receipt cannot trigger import. Confirm the agent ID again before force/keep-host undo. No replay after a lost write acknowledgement. |

## Verification and remaining boundary

- Flutter regression suites: `workspace_profiles_navigation_test.dart` enters both production More menus over a loopback cookie/ticket server, edits another profile's persona, cancels/starts/verifies a backup, discovers a Cloud candidate, refuses an unsigned-in destination, and revokes the UI on account mutation. `profile_admin_contract_test.dart` checks lifecycle, masked fields, pairing, QR apply, signatures, staged-home receipts, bytes/offsets, PID substitution, partial restore, reopen and undo. `portable_profile_bundle_test.dart` checks reviewed-only archives and bounds. `remote_workspace_wire_test.dart` covers the underlying transport fences.
- Independently exercised the **pinned Hermes** FastAPI chunk/restore handler, real whole-home backup/import/byte-for-byte undo, messaging-off/undo, and a platform plugin scoped to a secondary profile. Python ran in a network-denied macOS sandbox, with writes confined to disposable test data. A pinned host export was read and rebuilt by Dart, then imported by the pinned Python importer. Persona and skill matched and the fixture credential was absent.
- No live Cloud account, Telegram bot, personal gateway or billing. These are not signed/package builds or on-device picker/QR scan tests. No new native or copyleft dependency: `qr` 3.0.3 is BSD-3-Clause, and its `meta` dependency was already locked.
- **Open F13 detail:** a reviewed bundle can carry Desktop's existing `desktop.json` intact. Ares does not yet produce or adopt a Desktop skin/theme and pane layout for the imported profile. On this parent, Classic and NextGen appearance is device-wide; in `v5/shell`, saved layouts contain session/page references owned by an installation. Neither raw preference copying nor resolving foreign session IDs against a recipient gateway would be safe. This needs the shell/appearance integration and an owner-independent layout mapping. Preserve the overlay without executing it until then.
- A server restart before the first import acknowledgement/undo receipt leaves an unknown outcome: the pinned action API has no durable operation identifier for import. Do not guess from a later action named `import`. Recovery is available for a previously witnessed matching undo point.
